# Anamnesis

Anamnesis is a personal problem review system built around a simple idea:

> Solving a problem once is not the same as truly learning it.

Most platforms focus on getting accepted submissions. Anamnesis focuses on retaining the underlying ideas behind those solutions over time.

The application helps users revisit previously solved problems through a structured review process, encouraging active recall of approaches, patterns, mistakes, and implementation details before they fade away.

---

## Why I Built This

After solving hundreds of problems, I noticed a recurring issue:

* I could solve a problem today.
* I understood the solution completely.
* A few weeks later, I remembered that I had solved it, but not how I solved it.

The problem was not understanding.

The problem was retention.

Anamnesis was created to make problem solving more deliberate by treating solved problems as knowledge that needs maintenance, not as tasks that are permanently completed.

---

## Core Idea

Every solved problem enters a review cycle.

Instead of repeatedly reading old solutions, the goal is to:

1. Re-attempt the problem from memory.
2. Compare the new solution with previous attempts.
3. Track how understanding evolves across reviews.
4. Preserve insights that would otherwise be forgotten.

A problem is reviewed only a limited number of times, focusing on long-term retention rather than endless repetition.

---

## How It Works

### Adding Problems

Problems can be added and stored with relevant context, including:

* Problem title
* Platform
* Difficulty
* Tags
* Solution
* Notes

The objective is to preserve enough information to make future reviews meaningful.

### Review Cycle

Each problem follows a predefined review schedule.

During a review, the user attempts the problem again before looking at previous solutions. This encourages genuine recall rather than passive reading.

### Solution Evolution

Every review stores a new version of the solution.

This creates a timeline of understanding that makes it possible to observe:

* Changes in thinking
* Better implementations
* Simplified approaches
* Recurring mistakes
* Growth in problem-solving ability

Over time, the solution history becomes a record of learning rather than just a collection of accepted answers.

---

## What Anamnesis Is Not

Anamnesis is not:

* An online judge
* A competitive programming platform
* A problem recommendation engine
* An AI tutor

There are already excellent tools for those purposes.

This project focuses on a different problem:

> Remembering and retaining what you have already learned.

---

## Current Status

This is an actively developed personal project.

The core review workflow is being built and refined through actual usage. The goal is to create a system that remains useful in day-to-day problem-solving practice rather than one that simply accumulates features.

---

## Design Principles

The project is guided by a few simple principles.

### Keep It Practical

Features should solve real learning problems rather than exist for the sake of complexity.

### Active Recall Over Passive Consumption

Learning happens when information is retrieved from memory, not when it is repeatedly reread.

### Minimal Friction

Adding and reviewing problems should require as little effort as possible.

### Learning Over Archiving

The goal is not simply to store solved problems but to build a system that helps retain the ideas behind them.

## Philosophy

Most problem-solving platforms answer the question:

> "Can you solve this problem?"

Anamnesis tries to answer a different one:

> "Will you still remember how to solve it six months from now?"
